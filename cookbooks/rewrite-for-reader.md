# 判断基準が伝わらない文章を、読み手が使える形にしたい

自分が送る依頼: `$make-it-clear` → 会話に示されただけの文章を反映したい場合は更新を依頼。

エージェントの書いた PR description で、判断基準・責任・条件・挙動が推測に頼る例です。
レビューコメント、手順書、コードコメントにも同じように使えます。

## 1. 対象を指定して書き直す

```text
$make-it-clear pr#123
```

対象を省くと、その会話でエージェントが最後に書いた PR description、レビューコメント、
手順書、コードコメントが対象になります。
ファイルや、貼り付けた文章も指定できます。ディレクトリは指定できません。

対象の文章から、読み手が最初に必要とする判断基準、実行者と責任、条件と操作、失敗・例外を取り出します。
取り出した内容を、判断や実行が起きる場所の近くへ配置します。
原文にある具体的な名詞・動詞・条件は保存し、抽象的な表現に置き換えません。
判断・操作の分岐に直結する不明だけを、関連する確認と同じ返信にまとめて尋ねます。
不要な経緯や前置き、同じ内容の繰り返しは削ります。
PR template の必須項目とツール向けの記述は変えません。
参照の有無が不明な見出しも、既存アンカーを維持できなければ変更・統廃合しません。

修正前後を比較し、必要な情報の欠落や意味の変更がないか確認します。
主語や因果関係の明示は、原文にある情報か、原文から一意に読み取れる内容に限ります。
差分・コードだけに書かれた情報は補いません。
分担が有効なら検出・点検を並列化し、書き直しは一人が統合します。
短くすること自体は目的ではないため、直す箇所がなければ、変更なしと報告されます。
原文の事実関係そのものの検証と、コードの構造の変更は行いません。

## 2. 書き直した文章を確認し、必要なら反映を頼む

| 対象 | 反映 |
| --- | --- |
| Git で元の内容を戻せるファイル | そのまま編集される |
| その会話でエージェントが書いた、ファイル内の未 commit の文章 | その範囲だけが編集される |
| それ以外すべて | 書き直した文章が会話に示されるだけ |

Git で元の内容を戻せるファイルとは、追跡済みで、未 commit の変更がないファイルです。
未 commit の文章のうち、ユーザーや他の人が書いた部分、その会話より前からあった変更、
エージェントが書いたと区別できない部分は編集されません。
エージェントが書いた範囲を直すことでほかの部分にも変更が及ぶ箇所は、会話に示されるだけです。
シンボリックリンクは、リンク先の実体で判断されます。
PR description や投稿済みのコメントは、この skill では更新されません。
反映するなら、示された文章を確認してから頼みます。

```text
この内容で PR description を更新して。
```

削ってよいか判断できなかった記述は残り、報告されます。

## 完了の目安と次の依頼

読み手が判断基準・責任・条件・挙動を推測なしで再構成でき、必要な位置で見つけられることです。
情報の欠落や意味の変更を照合した結果も報告されます。確認できなかった判断材料は分けて示されます。
書き直した文章を PR に含めるなら、[PR 作成の例](review-and-pr.md) を参照してください。
