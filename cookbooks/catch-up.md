# 作業の状況と、次に判断することを知りたい

自分が送る依頼: 現在の状況と判断事項の説明を依頼。

自動で使われる skill: `catch-up`。

実装を任せているうちに説明が増え、何が終わり、自分が何を決めればよいか分からなくなった例です。
作業を追加する前に、現在の状況と判断材料を整理してもらいます。

## 1. 状況の説明を頼む

```text
今の状況と、私が判断する必要のあることを説明してください。
当初の依頼から何が変わり、どこまで終わっているかも知りたいです。
```

状況の説明を頼むと、`catch-up` が使われます。
判断待ちがあるか、何が完了して何が未解決か、選ぶ案ごとの影響が説明されます。
判断を求める点がなければ、無理に選択肢は作りません。

## 2. 判断材料を読んで返答する

例えば、タスクを削除する仕様で進めていたところ、他の記録が参照していると分かった場合です。
すぐ消す案と、非表示にして参照を残す案の違いを確認して選びます。

```text
他の記録から参照できなくなるのは困るので、非表示にして残す案にします。
この変更に影響する仕様と実装を揃えて、作業を再開してください。
```

まだ分からなければ、判断できない点だけを聞きます。

```text
非表示にして残す場合、通常の一覧と過去の記録では、それぞれ何が見えますか。
```

## 完了の目安と次の依頼

完了したこと、残ったこと、自分が選ぶ必要のあることを理解できている状態です。
判断待ちがあれば、選んだ案と再開する範囲を伝えます。
判断待ちがなく、未完了の作業を任せたい場合は、そのまま続行を頼めます。
