# 実装と文書の食い違いを直したい

自分が送る依頼: 古くなった文書の更新を依頼。

自動で使われる skill: `verify-change`。

CLI にオプションを追加したのに、README の使い方や使用例を更新していない例です。
現在の skill に文書の整合だけを担う専用のものはないため、通常の依頼として頼みます。

## 1. 実装の変更をもとに、古い説明を探して直す

```text
今回の CLI の変更で古くなった README、使用例、オプション一覧を洗い出してください。
実装とテストを確認して、説明と例を現在の動きに揃え、文書の検証までお願いします。
実装は変えず、判断できない食い違いは報告してください。commit・push は不要です。
```

変更した説明だけでなく、同じ使い方が載る他の箇所にも影響がないか確認します。
文書の説明が正しく、実装側を直すべき場合もあります。
合意した仕様と食い違う場合は、どう直すか相談します。

## 2. 利用者がまねする例を確かめる

オプション一覧だけ更新され、実行例は古いまま、という漏れも確認します。
確認してほしい使い方を具体的に伝えられます。

```text
README の実行例も、新しいオプションを含むものにしてください。
その例で意図した出力になるか、安全なローカルの入力で確認してください。
```

文書の lint、ローカルリンク、影響する使用例など、変更に合う方法で検証します。
外部の実データへの書き込みを伴う例など、実行できなかったものは、その範囲と理由を確認します。

## 完了の目安と次の依頼

対象の説明や例が現在の仕様・実装と一致し、文書の検証結果を確認できていることです。
未決の食い違いがあれば、何を正しい仕様とするかを決めてから対応します。
共有するなら、[PR 作成の例](review-and-pr.md) を参照してください。
