# 不具合を直したい

小さい修正と、原因の調査が必要な修正では、頼み始める内容が変わります。
どちらも、期待する動きと実際の動きを伝えると、何を直すかが明確になります。

## 小さいバグを直す

自分が送る依頼: 不具合の修正を依頼。

自動で使われる skill: `tdd`、`verify-change`。

空の入力はエラーにする仕様なのに、タスク名が空でも保存できてしまう例です。

```text
タスク名を空にして保存しても、エラーにならず保存できてしまいます。
空ならエラーにする既存仕様に合わせて直してください。
再発を防ぐテストと動作確認までお願いします。commit・push は不要です。
```

コードの修正には `tdd` が使われます。
`verify-change` が完了前の検証を担当します。
原因が不明な失敗を調べるときは、`debug-failure` も使われます。

返答では、空の入力が保存されないことと、通常の入力は保存できることを確認します。
片方しか確かめられていなければ、足りない確認を伝えます。

```text
通常のタスク名なら、これまでどおり保存できることも確認してください。
```

## 原因不明の不具合を直す

自分が送る依頼: 原因の調査と修正を依頼。

自動で使われる skill: `debug-failure`、`tdd`、`verify-change`。

タスクがあるときは使えるのに、最後の 1 件を消すと画面が真っ白になる例です。

```text
一覧を開いたまま最後のタスクを削除すると、画面が真っ白になります。
期待する動きは「タスクがありません」と表示されることです。
同じ操作で再現し、原因を特定して直してください。
修正後の検証までお願いします。commit・push は不要です。
```

再現条件と原因を確かめてから、修正と検証へ進みます。
エラー文や実行したコマンドがある場合は、秘密情報を除いて添えます。

例えば「空の一覧を最初から開く」ことしか確認されていなければ、元の操作との差を伝えます。

```text
不具合が起きるのは、一覧を開いたまま最後の 1 件を削除したときです。
その操作で直っているかも確認してください。
```

## 完了の目安と次の依頼

元の再現手順で期待どおりに動き、関連する既存の動きも検証されていれば完了です。
再現できない場合は、未解決の条件と、追加で必要な情報を確認します。

原因だけ知りたいなら、最初の依頼を「原因と修正案を教えて。変更はまだ不要」に変えます。
修正を共有するなら、[PR 作成の例](review-and-pr.md) を参照してください。
