# 依存関係を更新して、今のコードも動くようにしたい

自分が送る依頼: `$update-deps`。

自動で使われる skill: コードを修正する場合は `tdd`、変更後の確認には `verify-change`。

TypeScript を更新したいものの、型エラーや設定の変更が必要になるか分かりません。
依存関係だけでなく、必要な追従修正と検証まで任せる例です。

## 1. 更新するものを指定する

次の `typescript` は例なので、更新したい依存関係の名前に置き換えてください。

```text
$update-deps
typescript を最新の安定版へ更新してください。
必要なコードや設定の修正と、検証までお願いします。
```

使うバージョンが決まっていれば、名前とバージョンを一緒に伝えます。
指定があればそのバージョンを優先し、指定がなければ最新の安定版を目標にします。

更新方法は、そのプロジェクトの設定や依存関係の管理方法から判断されます。
互換性を保つために必要な関連依存関係や、コード・設定・テストの修正も含みます。
この skill は commit・push・公開をしません。

## 2. 更新結果と影響を確認する

次の点を確認します。

- 指定した依存関係の更新前後のバージョン。
- 互換性のために加えた関連更新と、コードや設定の変更。
- テスト、型チェック、lint、build などの検証結果。
- 未確認の範囲と、目標のバージョンに届かなかった場合の理由。

検証できなかった使い方があれば、報告された手順で確認します。
目標に届かなかった場合は、理由をもとに、必要な環境の変更や更新範囲を検討します。
追加の対応を頼むときは、その対象を伝えます。

```text
報告にあった型エラーについて、今回の更新に必要な範囲で修正し、再度検証してください。
commit・push はまだ不要です。
```

## 3. 必要なら PR として共有する

更新内容と検証結果を確認できたら、[変更をレビューして PR を出す](review-and-pr.md) へ進めます。
共有しない場合は、ローカルでの確認までで終えられます。

## 完了の目安

目標のバージョンへ更新され、必要な追従修正と検証が済んでいることです。
未達の場合は、更新できた範囲と残る制約を把握し、続けるか判断します。
