# 出した PR をマージできる状態にしたい

GitHub にある PR について、起きている問題に合う項目を選びます。
CI は、GitHub 上で自動実行されるテストや lint などの検証です。
競合は、PR と取り込み先の変更が重なり、自動で統合できない状態です。

対象のプロジェクトを開き、PR 番号と、GitHub の認証・権限があることを確認します。
下の `pr#123` は、自分の PR 番号に置き換えてください。
どの呼び出しも、対象 PR の修正と commit・push まで進みます。

自動で使われる skill: コード修正には `tdd`、変更後の確認には `verify-change`。
原因不明の失敗を調べる場合は `debug-failure` も使われます。これらを別に呼ぶ必要はありません。

## レビュー指摘に対応したい

自分が送る依頼: `$fix-pr` → 返信案を確認して承認。

呼び出し後の処理: 指摘の検証 → 修正 → 検証 → commit・push → 返信案。

### 依頼する

```text
$fix-pr pr#123
```

未解決の指摘を確認し、コードやテストで妥当性を確かめたうえで、必要なものだけ修正します。
検証と commit・push のあと、レビュースレッドへの返信案が返ります。

### 結果を確認して次へ進む

対応した指摘、修正しなかった指摘と理由、検証結果、push の結果を確認します。
返信案が指摘への回答になっているかも読みます。
返信は、文面を確認して承認するまで送信されません。

```text
提示された返信案をすべて、その文面で送信してください。
```

一部だけ送る場合は、承認する返信案を指定します。
返信文を変えたい場合は、変更した文面を伝えます。

### 完了の目安

必要な修正が PR に反映され、未解決の指摘とその理由を把握できていることです。
返信も頼んだ場合は、承認した文面が送信されたことまで確認します。

## CI の失敗を直したい

自分が送る依頼: `$fix-ci`。

呼び出し後の処理: 原因の調査 → 修正 → 検証 → commit・push。

### 依頼する

```text
$fix-ci pr#123
```

失敗した処理のログから原因を調べ、コード・テスト・CI 設定で解決できる問題を修正します。
ローカルで検証して commit・push します。
外部サービスや権限が原因の場合は、コードを無理に変えず、原因が報告されます。

### 結果を確認して次へ進む

原因、修正内容、ローカルの検証結果、push の結果を確認します。
PR 上で、修正を含む最新の commit に対する CI の実行結果も確認してください。
ローカルの検証が通ったことと、GitHub 上の CI が通ったことは、それぞれ確認します。

失敗が残る場合は、失敗した検証を伝えて、同じ PR に再度 `fix-ci` を呼べます。
権限や外部サービスの対応が必要なら、報告された対応を済ませてから再確認します。

### 完了の目安

対象の CI が通っていることです。
外部の問題で解決できなければ、未解決として、原因と必要な対応を把握します。

## 競合を解消したい

自分が送る依頼: `$fix-conflicts`。

呼び出し後の処理: 取り込み先を merge → 競合解消 → 検証 → commit・push。

### 依頼する

```text
$fix-conflicts pr#123
```

取り込み先ブランチの最新変更を PR のブランチへ merge し、両方の変更意図を確認して競合を解消します。
検証して commit・push します。rebase や force push は使いません。

### 結果を確認して次へ進む

取り込んだブランチ、競合を解消した箇所、解消時の判断、検証結果を確認します。
仕様の選択を求められた場合は、両方の変更で何を残すべきかを伝えます。

PR 上で競合が解消されたことと、最新の commit に対する CI の結果を確認します。
CI が失敗していれば、上の「CI の失敗を直したい」に進めます。

### 完了の目安

両方の変更意図を保った解消結果が PR に反映され、競合がなくなっていることです。
残っている検証の失敗や仕様判断があれば、確認して対応します。

## PR の指定を省略できる場合

現在のブランチに対応する PR が対象なら、`pr#123` を省略できます。
別のリポジトリなら、`owner/repo#123` の形で指定します。
たとえば `$fix-ci owner/repo#123` です。`owner` と `repo` も対象に置き換えてください。
