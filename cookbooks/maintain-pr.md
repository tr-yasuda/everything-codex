# 出した PR をマージされるまで任せたい

GitHub にある PR について、依頼したい対応を選びます。
CI は、GitHub 上で自動実行されるテストや lint などの検証です。
競合は、PR と取り込み先の変更が重なり、自動で統合できない状態です。

対象のプロジェクトを開き、PR 番号と、GitHub の認証・権限があることを確認します。
下の `pr#123` は、自分の PR 番号に置き換えてください。

自動で使われる skill: コード修正には `what-breaks` と `tdd`、変更後の確認には `prove-it`。
原因不明の失敗を調べる場合は `root-cause` も使われます。これらを別に呼ぶ必要はありません。

## まとめて任せたい

自分が送る依頼: `$babysit pr#123` → 必要なら返信案を承認。

呼び出し後の処理は次のとおりです。

1. PR の状態を確認する
2. 競合・CI・レビュー指摘を修正する
3. 検証して commit・push する
4. CI と新しいレビューを待って再確認する
5. マージされたら止まる

### 依頼する

```text
$babysit pr#123
```

PR の最新状態を GitHub から確認し、merge conflict、失敗している CI、未解決のレビュー指摘を直します。
Draft のままでも監視と修正は続きます。
push のたびに CI と新しいレビューを待ち、最新の commit の状態で確認し直します。
merge-ready になっても止まらず、PR がマージされるまで監視を続けます。
待機コマンドが timeout したり、レビュー待ちで今すぐできる作業がなかったりしても、監視は止まりません。
仕様判断や返信文面の承認が必要なときは、回答待ちで中断し、回答後に監視を再開します。

### 結果を確認して次へ進む

監視を終了または中断したときは、理由と対象 PR、確認した HEAD、行った対応、残っている問題が報告されます。

| 状態 | 次に自分がすること |
| --- | --- |
| マージ済み | 完了を確認する |
| close 済み | マージされなかった理由を確認する |
| 仕様判断の回答待ち | 報告された仕様を選び、回答する。回答後は監視が再開する |
| 権限・外部サービスの対応待ち | 権限や外部サービスを整え、もう一度呼ぶ |
| 進展なし | 試した対応と残っている問題を読み、方針を伝える |
| 返信の承認待ち | 返信案を確認し、承認する文面を伝える |
| 続行不可 | 報告された理由を確認する |

<!-- shared-text:babysit-approval:start -->
返信は、ユーザーが文面を承認してから送信します。
<!-- shared-text:babysit-approval:end -->

### 完了の目安

PR がマージされていることです。
それ以前に終了または中断した場合は、残っている問題と、自分が判断することを把握できていることです。

## PR の指定を省略できる場合

現在のブランチに対応する PR が対象なら、`pr#123` を省略できます。
別のリポジトリなら、`owner/repo#123` の形で指定します。
たとえば `$babysit owner/repo#123` です。`owner` と `repo` も対象に置き換えてください。
