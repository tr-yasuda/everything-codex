# CLAUDE.md・AGENTS.md を改善したい

自分が送る依頼: `$refine-instructions` → 差分と報告を確認して PR にする。

開発が進むうちに、指示書が実態と合わなくなった例です。
存在しないコマンドや lint で検出済みのルールが残る一方で、エージェントが毎回間違える手順は書かれていません。

## 1. 改善を依頼する

```text
$refine-instructions
```

Git が追跡している CLAUDE.md・AGENTS.md が対象になります。サブディレクトリのものも含みます。
特定の指示書だけを改善するときは、パスを続けて書きます。
個人の `~/.claude/CLAUDE.md` などは、指定したときだけ対象になります。

作業中にエージェントの間違いを訂正した会話で呼び出すと、その訂正も追記の根拠になります。
足されるのは、チームの誰が作業しても当てはまる事実だけです。

エージェントは指示書を、lint などの設定、タスク定義、既存コード、関連文書と照らし合わせます。
次の改善を、作業ツリー上で直接編集します。commit・push はされません。

- 足りない事実を追記する
- 「適切に」のような曖昧な記述を、確かめられる基準に書き換える
- コードや設定と食い違う記述を現状に合わせる
- ツールで検出済みのルールや、コードを見れば分かる内容を減らす

## 2. 報告と差分を確認する

報告には、自分が判断する必要のあることだけが 1 件 1 行で並びます。
それ以外は、修正したファイルと検証の結果だけが伝えられます。
変更の根拠や移動などの候補の詳細は、聞けば示されます。
差分を見て、チームで守りたい内容が消えていないか、追記が正しいかを確認します。
直したい点があれば、理由と一緒に伝えます。

```text
「生成ファイルは手で編集しない」は残して。lint では検出していないので。
```

次の記述は編集されず、確認事項や候補として報告されます。必要なら答えるか、別に依頼します。

- 基準を確かめられず、具体化できなかった記述
- どちらが正しいか判断できない、コードとの食い違い
- まだツールで検出していないルール。lint 設定へ移せる
- 特定のディレクトリや作業だけに関わる指示。サブディレクトリの指示書などへ移せる
- チームで合意したと確認できない個人の好み。個人の指示書へ移せる

## 完了の目安と次の依頼

指示書に、ツール・コード・ほかの文書から得られない事実が、行動を決められる形で書かれていることです。
文書の検証が通っていることも確認します。
確認事項が残っていれば、答えてから直します。
チームで確認するには PR にします。[PR 作成の例](review-and-pr.md) を参照してください。
