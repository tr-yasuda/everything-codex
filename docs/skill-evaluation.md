# Skill の実行評価

機能追加とバグ修正の試行で、成功したテストの不要な再実行を各 1 回確認しました。
`tdd` と `prove-it` の検証結果を再利用する条件を明記し、変更後の試行では重複がなくなりました。
今回の試行では、必要な Skill の選択漏れは見つかりませんでした。

2026-11-18 に、変更前の `6ab7a83` と、検証結果の再利用を明記した手順で比較しました。

## 評価方法

過去の起動順序や実行内容を確認できる記録は、リポジトリ内には見つかりませんでした。
代わりに、隔離した一時ディレクトリで次の依頼に対応しました。
過去の実作業で問題が発生した証拠としては扱いません。

- 機能追加: 前後の空白除去と小文字化を行う内部関数で、途中の連続空白もまとめる。
- バグ修正: 数量 0 を省略と取り違える内部関数を修正し、省略時と他の入力の扱いを維持する。
- 文書修正: README の検証方法に lint のコマンドを追加する。
- 状況説明: 処理の変更だけが済み、テストと lint が未実施の作業の状況を説明する。

各作業には、会話を引き継がない新しい subagent を使いました。
特定の Skill の起動は指定せず、導入場所と、使用した Skill・検証結果の報告を求めました。
導入したのは `tdd`、`what-breaks`、`root-cause`、`prove-it`、`catch-up` のリポジトリ内の版です。

対象は、外部サービスや追加の依存関係を使わない Node.js の内部モジュールです。
コード変更では `node --test` と `node scripts/lint.mjs`、文書変更では lint だけを必要としました。
型チェック・build・公開 CLI・API・画面はありません。

Skill の読み込みと順序は、担当 subagent の報告に基づきます。
テストと lint の実行回数は、一時的な実行記録を親が読み、ソース・テストなどの hash と照合しました。
終了結果と追加の直接実行は担当の報告を確認し、最終成果物も親が点検しました。
詳細な実行履歴はリポジトリに保存しません。

## 変更前の結果

| 作業 | 必要だった確認 | 実際の結果 | 判定 |
| --- | --- | --- | --- |
| 機能追加 | 変更前の影響調査、RED と GREEN、最終差分・境界条件、lint | 必要な確認を実施。同じ内容のテストを成功後に再実行 | 重複 1 回 |
| バグ修正 | 原因確認、影響調査、回帰テスト、既存入力との互換性、lint | 必要な確認を実施。同じ内容のテストを成功後に再実行 | 重複 1 回 |
| 文書修正 | 差分確認、lint | README だけを修正し、lint 成功。アプリケーションテストは未実行 | 漏れなし |
| 状況説明 | 引き継ぎと差分の照合、未検証・判断待ちの説明 | 未検証と判断待ちなしを説明。編集や検証は未実行 | 漏れなし |

機能追加では `tdd` と `what-breaks` を変更前、`prove-it` を GREEN 後に読んだと報告されました。
バグ修正では `root-cause` も修正前に読んでいました。
文書修正では `prove-it`、状況説明では `catch-up` が使われました。

コードを変更した 2 件では、RED の失敗後に実装を変えて GREEN を確認していました。
その後、同じソースとテストで `node --test` をもう一度実行していました。
条件の追加や内容の変更がないまま、成功した検証を繰り返しているため、各 1 回を重複と判定しました。
RED から GREEN への再実行と、別の入力条件の検証は重複に数えていません。

## 改善した範囲

変更前の `tdd` は、REFACTOR の点検で変更しなくても、関連テストの再実行を求めていました。
また、`prove-it` の再利用の説明は、その手順内で済ませた検証に限られていました。

- `tdd`: 点検だけなら直前の GREEN を使い、変更した場合に再実行する。
  確認した振る舞い、コマンドと結果、未確認の範囲を完了前の検証へ引き継ぐ。
- `prove-it`: 実装中の検証結果も、振る舞いと条件、コマンドや操作、観察結果を確認して使う。
  結果に影響する変更と未確認の条件は、追加で確かめる。

## 変更後の結果

コード変更の 2 件を、同じ初期コード・既存テスト・依頼で、新しい subagent に実行させました。

| 作業 | 変更前のテスト実行 | 変更後のテスト実行 | 重複の変化 |
| --- | --- | --- | --- |
| 機能追加 | RED、GREEN、変更なしで再実行の 3 回 | 2 サイクルの RED と GREEN の 4 回 | 1 回から 0 回 |
| バグ修正 | RED、GREEN、変更なしで再実行の 3 回 | RED と GREEN の 2 回 | 1 回から 0 回 |

機能追加では、最初の実装後に CRLF の条件をテストへ追加し、失敗を確認して実装を修正していました。
この追加に伴うテストと lint の再実行は、対象が変わっているため必要な検証です。
実行回数全体の減少を改善の条件にはしていません。

両件とも最終テストと lint は成功し、必要な Skill の読み込みタイミングも変更前と同様でした。
最終報告には、確認した振る舞いと、型チェック・build などの適用外または未確認の範囲が書かれていました。

## 評価の限界

各条件を 1 回ずつ試した結果であり、通常利用での起動漏れの頻度や、今後の起動を保証するものではありません。
導入場所と評価用の報告を依頼に明示しているため、通常の依頼と同じ条件でもありません。
合意変更による中断、外部サービス、複数モジュール、環境変更、独立検証が必要な作業は未評価です。

今回の結果から、起動を強制する仕組みを追加する根拠は得られていません。
今後も、その作業に必要だった確認と実行結果を照合し、確認できた問題の範囲で改善します。
