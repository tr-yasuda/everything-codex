# 記録の読み書き

Node.js 24、Git、`flock` を使う。追加の npm パッケージは不要となる。
`skill_dir` に、この skill のディレクトリの絶対パスを設定する。
コマンドは、判断の対象となるリポジトリ内で実行する。

## 一覧と参照

```bash
node "$skill_dir/scripts/store.mjs" list
node "$skill_dir/scripts/store.mjs" read '<id>'
```

`list` は `version` と、各記録の `id`、`title`、`scope`、`status` を返す。
`read` は `version` と、指定した `record` を返す。`<id>` は一覧の ID に置き換える。
記録がないときの一覧は `{"version":null,"records":[]}` となる。

## 保存する内容

更新の入力は JSON とし、標準入力で渡す。
判断の内容をコマンドの引数や、リポジトリ内の入力ファイルに書かない。
シェルの here-document を使う場合は、区切りを引用して変数やコマンドの展開を防ぐ。

```bash
node "$skill_dir/scripts/store.mjs" save <<'JSON'
{
  "expectedVersion": null,
  "record": {
    "title": "読み込み API の失敗の返し方",
    "decision": "読み込み失敗は戻り値で返す",
    "reason": "呼び出し側で失敗する可能性とその扱いを追えるようにするため",
    "alternatives": "例外。成功時の記述は短くなるが、失敗への対処を忘れても型で気づけない",
    "scope": "今回追加する読み込み API。既存 API の変更は含まない",
    "reconsiderWhen": "呼び出し側で失敗を個別に扱う必要がなくなったとき",
    "source": "今回の会話で、ユーザーが戻り値で返す案に合意した"
  }
}
JSON
```

`expectedVersion` は、直前の `list` または `read` が返した `version` をそのまま使う。
上の `null` は、まだ記録がない場合だけの例となる。
版はリポジトリ全体で共通となり、別の記録が更新された場合も競合を返す。

`title`、`decision`、`scope`、`source` は必須となる。
`reason`、`alternatives`、`reconsiderWhen` は、省略すると「記録なし」で保存する。
渡す値は空でない文字列とし、入力に管理用の ID、状態、日時を混ぜない。
記録の ID、UTC の記録日時、状態、履歴はスクリプトが管理する。

成功時は、新しい `version` と、保存した記録の `id`、`status` を返す。

## 訂正・置換・撤回

各コマンドも JSON を標準入力で受け取る。

| コマンド | 入力 | 結果 |
| --- | --- | --- |
| `correct` | `expectedVersion`、`id`、`record` | 同じ ID の内容を訂正し、変更前の値と訂正日時を履歴に残す |
| `replace` | `expectedVersion`、`id`、`record` | 新しい判断を保存し、元の判断を「置換済み」にする |
| `retract` | `expectedVersion`、`id`、`reason` | 判断を「撤回済み」にし、理由と撤回日時を履歴に残す |

`id` は対象の記録の ID とする。
`correct` と `replace` の `record` は、保存と同じ項目で内容全体を渡す。
`retract` の `reason` を省略すると、「記録なし」で保存する。

置換後の元記録には `replacedBy`、新しい記録には `replaces` が入り、互いの ID を示す。
置換と撤回は「採用」の記録だけを対象とする。訂正は状態を変えない。
どの操作も元の判断を削除しない。

## 保存先と更新の保証

Git の共通管理ディレクトリの絶対パスを実体に正規化し、SHA-256 で識別子を求める。
同じ共通管理ディレクトリを使う worktree は同じ記録を参照し、別の clone は別の記録を使う。

保存先は `$HOME/.local/state/record-decision/<識別子>/` となる。
判断ごとの内容を `records.json` 内に保持し、`.lock` を読み書きの排他に使う。
専用ディレクトリの権限は `0700`、ファイルは `0600` とする。
ホームディレクトリ、`.local`、`state` は本人または root の所有とし、group・other の書き込み権限を拒否する。
これらの親ディレクトリの `0755` は許容する。
記録とロックファイルはシンボリックリンクを拒否し、ハードリンク数が `1` の通常ファイルだけを扱う。

参照は共有ロック、更新は排他ロックを取得する。
更新では、ロックの取得後に版を照合し、新旧の判断をまとめた一時ファイルを作って置き換える。
読者からは更新前か更新後のどちらかが見える。
一時ファイルは同じ本人用領域内に作り、通常終了時には取り除く。
参照だけでは、保存先やロックファイルを作らない。

ロックは 1 回のコマンド実行中だけ保持する。
`.lock` は削除・置換しない。異なるファイルへのロックに分かれると、排他が成立しなくなる。
データや履歴も直接編集せず、必ずスクリプトを通す。

## エラー

失敗時は、標準エラー出力に `{"error":"CONFLICT"}` のようなコードを返す。
入力本文や内部の例外メッセージは出力しない。

| 終了コード | エラー | 扱い |
| --- | --- | --- |
| `3` | `CONFLICT` | 読んだ後に記録が変わった。最新の記録を読み、今回の内容と照合する |
| `4` | `BUSY` | 別の操作が実行中。その実行では読み書きせずに終了する |
| `1` | `INVALID_INPUT`、`USAGE` | 入力形式やコマンドを直す |
| `1` | `NOT_FOUND`、`INACTIVE_RECORD` | 記録の ID や現在の状態を確認する |
| `1` | `UNSAFE_LOCATION`、`UNSAFE_STORAGE` | 保存先の場所・権限・所有者・リンクを確認する |
| `1` | `CORRUPT_STORE` | 記録が壊れているか未対応の形式。初期化や上書きはしない |
| `1` | `LOCK_ERROR`、`STORE_ERROR` | 実行環境、アクセス権限、Git、`flock` の有無を確認する |

競合や実行中を理由に、版の確認を省略して上書きしたり、自動で再試行し続けたりしない。
競合後に元の判断が変わっていたら、変わった内容を伝え、保存内容の判断をユーザーに戻す。
