# Self-drive

## 目的と適用

複数の実装・調査タスクを、ユーザーが指定した範囲で自走して進める。
Codex CLI では `$self-drive <目標・タスク参照>` を使う。
Claude Code では `/self-drive <目標・タスク参照>` を使う。

この skill は自走の入口であり、coordinator の分解・委譲・統合、各 skill の実装・検証・承認条件を置き換えない。
対象タスクが完了するか、ユーザーが自走の停止を求めたら、このモードを終了する。
ユーザーの判断が必要なときは、判断材料を示して作業を止める。
ユーザーが判断を示し、元の依頼の範囲・権限・承認条件が変わらない場合は、同じ依頼の続きを再開する。
範囲・権限・承認条件が変わる場合は、変更後の依頼として確認してから進める。
自走によって、元の依頼の範囲・権限・承認条件を広げない。

## タスクの確認と選択

タスクの正本は、ユーザーが指定した現在の情報源（依頼文・Issue・Jira など）から確認する。
接続済みツールで現在の状態を読める場合はそれを使い、読めない場合はユーザーにタスク一覧や内容の提供を求める。
過去の会話や記憶だけを正本として扱わない。

対象タスクを選ぶ前に、次を確認する。

- タスクの現在の内容、完了条件、依存関係、競合するファイルや共有資源
- 実行環境、接続済みツール、利用できる profile と subagent の制約
- 並列化できる作業と、直列に進めるべき作業
- 元の依頼に含まれる権限と、既存 skill が求めるユーザー承認

Issue や Jira の状態更新、担当者の変更、外部への投稿は、明示的に依頼されない限り行わない。
ハーネスがタスク一覧を提供する場合はそれを使い、独自の台帳を作らない。

## 進め方

独立して進められる作業は coordinator を使って分担する。
coordinator に渡す依頼には、元の目的、担当範囲、完了条件、適用されるプロジェクト指示と skill、承認条件、必要な結果と根拠を含める。
同じファイルや共有資源を並行して変更しない。

Subagent を使うときは、対象 profile の現在の設定と指示から、使用できる reasoning effort とその意味を確認する。
タスク難易度から effort への共通変換表を持たない。

- profile が effort を固定している、既定値を変えている、使用できる値が異なる場合は、その定義に従う。
- 専用 profile の指示が共通指示を置き換える場合は、profile 固有の選択基準と使用できる値を委譲文に引き継ぐ。
- effort が未定義・未対応・あいまいなときは、推測して置き換えず、ユーザーに確認する。

推論量を変えるためにモデルを切り替えない。

各タスクでは、適用条件が成立している既存 skill を使う。
実装・修正では最小限の変更を保つ。
コード変更前は `what-breaks`、失敗の原因を調べるときは `root-cause`、実装は `tdd`、差分を整理するときは `unslop` を適用する。
各タスクの完了前は `prove-it` に従い、差分と実際の動作を確認する。
各担当の完了報告だけを根拠にせず、成果物と検証結果を確認してから統合する。

## 止まる判断

次のいずれかに当たるときは、自走を続けずに判断材料を示してユーザーに確認する。

- 利用者から見える振る舞い、公開インターフェース、互換性、データの扱いで選択肢が複数ある
- 仕様や完了条件が不明確、またはタスク間で矛盾する
- effort の定義が使えない
- 破壊的・不可逆な操作、外部への投稿、Issue や Jira の状態変更が必要になる
- 権限、認証、機密情報の扱いが不明確になる
- 必要な検証ができない、または検証結果が矛盾する

確認を求めるときは、選択肢ごとの影響、推奨、推奨しない理由、確かめていないことを示す。

## 完了報告

完了したタスク、実際に確認したこと、実行した検証、残っているタスク・判断・未確認事項を報告する。
タスク管理システムや外部サービスの状態は、確認できた現在の状態だけを報告し、更新結果は含めない。
