# Claude Code の補足

## 実行方法の選択

通常の Subagent で足りる場合は、それを使う。`Agent` など、現在公開されている機能の仕様を確認する。
独立した作業を並行して進める場合は、利用可能なバックグラウンド実行を選ぶ。
前景と背景では、使えるツールや結果の返る先が異なる。委譲先で必要な操作を行えるか確かめる。

`SendMessage` などの通信機能が利用可能なら、結果の共有や追加指示に使う。
起動時に返された識別子や名前で宛先を確認する。
名前付き起動が Agent Teams のメンバー起動になる設定もあるため、名前だけで実行方式を判断しない。

編集の分離が必要なら、利用可能な `isolation: worktree` などの標準機能を検討する。
Worktree の基点が親の `HEAD` とは限らないため、必要な先行成果と未 commit の変更があるか確認する。

Agent Teams は、共有タスクや継続的な相互通信が必要で、機能が有効な場合の選択肢とする。
必須にはせず、自動で有効化しない。Subagent と同じ制約で動くとは考えない。

## 確認済みの範囲

2026-11-18 に確認した公式資料では、Subagent の並列実行、再委譲、通信、Worktree 分離が案内されている。
階層の深さと同時実行数には環境側の制限がある。旧バージョンや制限されたツール構成にも同じ機能があるとは限らない。
入れ子の結果の返り先や待機動作には、対話実行と非対話実行などの違いがある。
親は、下位の成果が揃ったかを実際の通知と結果で確かめる。

Agent Teams は実験的機能で、既定では無効。入れ子のチームには対応していない。
チームの再開や終了にも制約があるため、必要な場合に公式資料と現在の実行状態を確認する。
