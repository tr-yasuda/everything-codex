# Using Git Worktrees

## 作業場所を確認する

Git のルート、現在の branch、未コミット差分、worktree 一覧を確認する。
既存の作業場所で依頼を続けられるなら再利用する。
読み取りや提案だけのために worktree を増やさない。
未コミット差分を勝手に移動、削除、stash しない。

## 分離する

ユーザー指定とリポジトリの配置規約を優先する。
規約がなければ .worktrees/ を候補とする。
リポジトリ内に作る場合は、作成前に Git の除外対象か確認する。
除外されていなければ、対象ディレクトリだけを除外して再確認する。

branch 名は既存の命名規約と作業内容から決める。
同じ目的の worktree があれば再利用し、同名 branch と衝突させない。
新規作成では git worktree add を使い、現在の checkout を切り替えない。

## 初期状態を確認する

必要なセットアップと関連する検証を、新しい作業場所で実行する。
開始前からの失敗を記録し、変更後の失敗と混同しない。
利用する path、branch、初期検証の結果を短く報告する。

終了時も worktree を自動削除しない。
片付けを依頼された場合は、未コミット・未保存の作業がないことを確認する。
未統合の commit は、保存先または明示された破棄の指示を確認する。
削除には git worktree remove を使い、強制削除で問題を隠さない。
