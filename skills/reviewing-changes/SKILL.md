# Reviewing Changes

## レビュー対象を確定する

要求、対象差分、関連コード、テスト、検証結果を読む。
PR なら比較元と比較先を確認し、変更の前後を把握する。
実装者の完了報告だけを根拠にしない。

## 確認する内容

- 要求した振る舞いを満たし、対象外の変更が混ざっていないか。
- 入力、失敗経路、互換性、状態の変化に問題がないか。
- テストが実装の形ではなく契約を検証し、回帰を検出できるか。
- 変更範囲に不要な重複、責務の混在、先回りした抽象化がないか。
- TDD 作業では、REFACTOR の対象と判断が記録されているか。

記録がない場合は、点検実施を推測しない。
実装中なら TDD の REFACTOR へ戻り、レビューのみなら未確認事項とする。

## 指摘を返す

具体的な発生条件、影響、根拠となる場所を添えて重大度順に示す。
好みや可能性だけの指摘を、不具合と同列に扱わない。
指摘がなければその旨と、確認できなかった範囲を伝える。
レビュー依頼だけではコードを変更せず、外部へ投稿しない。

修正した場合は、該当するテストと検証をやり直す。
完了確認は [verifying-changes](../verifying-changes/SKILL.md) に従う。
