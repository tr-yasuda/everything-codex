# Verifying Changes

## 完了条件と証拠

要求ごとに、どの結果で達成を確認するか決める。
対象リポジトリの指示、CI、既存スクリプトから検証コマンドを選ぶ。
テスト、型検査、lint、build は、それぞれが確認する範囲を区別する。

最終変更を反映した状態で検証し、出力と終了コードを読む。
対象が変わっていない有効な実行結果は再利用できる。
検証後に変更した場合は、その変更に影響される確認をやり直す。
一部のテスト成功を、全体の成功と表現しない。

## TDD の完了確認

TDD を使った場合は、各サイクルの記録を確認する。

- RED が意図した失敗だったこと。
- GREEN を実行して確認したこと。
- REFACTOR の点検対象と、変更内容または変更不要の理由。
- リファクタリング後も対象と関連テストが成功したこと。

REFACTOR 点検がなければ [tdd](../tdd/SKILL.md) の該当工程に戻る。
テストが通っていても、そのサイクルを完了と報告しない。

## 報告

実施した変更、確認コマンドと結果、未確認事項を短く示す。
既存の失敗と今回の失敗は、証拠がある場合だけ区別する。
実行不能な検証は、理由と確認できない範囲を伝える。
検証の障害を解消するためだけに、無関係な修正を広げない。

文書 skills の lint 成功は、エージェントの動作改善を証明しない。
動作を評価した場合は、シナリオ、観測結果、未評価の条件を分けて示す。
