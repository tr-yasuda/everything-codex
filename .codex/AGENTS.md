# 共通の作業方針

このファイルは ~/.codex/AGENTS.md として使う共通指示です。
特定の設定管理リポジトリや、その配置場所には依存しません。
作業対象のリポジトリに固有の指示がある場合は、その指示を優先します。

## 応答

- 日本語のです・ます調で、結論から簡潔に伝える。
- 実行結果と推測を区別し、未確認の内容を確認済みと報告しない。
- 重要な仕様が未確定の場合に質問し、合意済みの内容は聞き直さない。

## 作業場所

- Git 管理下のファイルを変更する前に、専用 worktree を用意する。
- main や起点の checkout では編集せず、同じタスクの worktree は再利用する。
- 準備には using-git-worktrees skill を使い、path と branch を伝える。
- ユーザーの未コミット差分を、勝手に移動、削除、stash しない。

## Skills

利用可能な skill の名前から定義を読み、必要な工程だけを使う。
skills/ が作業ディレクトリにあるとは仮定しない。

- development-workflow: 実装依頼に必要な工程を選び、完了まで進める。
- designing-changes / planning-changes: 仕様や複数工程の整理が必要な場合。
- systematic-debugging: 不具合の原因が分からない場合。
- tdd: 振る舞いの追加・修正を、1 つずつテストと実装で進める。
- reviewing-changes / verifying-changes: 差分を点検し、完了条件を確認する。
- finishing-changes: commit、push、PR など依頼された操作を仕上げる。
- responding-to-review: レビュー指摘を確認し、修正と再検証を進める。

TDD は各 GREEN 後の REFACTOR 点検と判断記録までを 1 サイクルとする。
点検未実施のまま、次の実装や完了報告へ進まない。
文書や設定の変更は、内容に合う lint や構文検証で確認する。
言語固有の規約と検証コマンドは、作業対象の設定や CI に従う。

必要な skill が見つからない場合は、その事実を伝える。
作業対象とは無関係なリポジトリを探索して補おうとしない。
ユーザーまたは適用される指示で委任が求められた場合に、エージェントを使う。
